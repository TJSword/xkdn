## 已确认的来源

公开入口 `https://tzzb.10jqka.com.cn/pc/index.html` 在业务脚本之前加载：

`https://s.thsi.cn/js/chameleon/chameleon.min.1792161.js`

直接读取该脚本并使用本地 Babel 解析器进行静态分析，随后仅提取编解码相关代码在无网络、无真实浏览器对象的隔离上下文中对照，未执行完整第三方脚本。独立 Node 实现与提取代码的 100 组合成输入编码结果一致。

其两组常量表分别包含 239、268 项，解析得到：

- `Fn = r[45]` 对应 Cookie 名称 `v`。
- `u[66]`、`u[68]` 分别对应 `document` 和 `cookie`。
- `jn` 对应 `hexin-v`，用作请求头名称。
- Cookie 写入时路径参数为 `/`；脚本中的保存期限参数为 `Fri, 01 Feb 2050 00:00:00 GMT`。这不是服务端校验有效期，也不代表浏览器最终保存期限。

核心调用链：

```text
chameleon 初始化及请求包装逻辑
  → D()
  → rt.update()
  → 更新内部状态并编码
  → Qn.setCookie(Fn, value, ...)
  → document[cookie] = ...
```

脚本中的实际写入调用为：

```js
function D() {
    var n = rt.update();
    return Qn.setCookie(Fn, n, o[248], A, t[215]), Zn.set(jn, n), n;
}
```

这是来源证据，不是可独立执行的生成代码；Fn、rt 等变量依赖闭包环境。

## 为什么前面的断点没有命中

业务文件 `708.5b8408ca.js` 内的通用 setCookie 并不是此脚本使用的工具。chameleon 有自己的 Cookie 工具，并使用 `u[66][u[68]]` 这类混淆访问方式，因此简单搜索 `document.cookie`、`["cookie"]` 不能覆盖该路径。

## 与 403 的关系

此前本机对照已确认：18 个 Cookie 字段中仅 v 不同；同一请求方式交替使用旧、新 v 时，旧值两次返回 Nginx 403，新值两次返回业务成功。

该对照支持“v 的状态是这次拒绝访问的关键变量”。当前静态检查进一步定位到生成来源，但不能据此确定服务器采用的全部校验规则、有效窗口、IP 绑定规则或云端可用性。

浏览器直接检查时，同花顺标签页提示“当前页面不支持开发者工具，请关闭后刷新页面”；没有修改页面绕过该提示。随后用户提供的断点截图已在运行时确认：名称参数为 v，调用链为 rt.update() → Qn.setCookie(...) → Cookie 写入。用户在选定调用帧执行只读表达式，确认 Fn 为 v、jn 为 hexin-v；所展示的 HTTP 200 stock_card 请求头含 Cookie v，没有单独的 hexin-v。

## 独立算法及请求前更新

用户已选择每次请求前生成，无需新增定时任务。

当前协议的 43 字节状态按固定宽度字段序列化，外层含版本字节、校验字节及逐字节变换后的状态，使用 URL 安全 Base64 编码为 60 个字符。编码校验是客户端协议的一部分，不能据此推断服务端全部风控规则。

`functions/getAccountObservation/tonghuashun-cookie.js` 实现状态校验、解码、更新及编码；`requestAccount()` 在每次发送前调用它。

- 以数据库中已授权浏览器生成的 v 为状态模板，不从空白状态伪造整套浏览器特征。
- 时间字段位于状态偏移 4、8，按当前服务端时钟的 Unix 秒更新；浏览器原脚本中的第一个时间字段来自 TOKEN_SERVER_TIME，本实现以当前主机时钟更新，已通过本机与云端实测，但未建立额外的远程校时流程。
- 偏移 12 的 UA 哈希与实际发送的 User-Agent 对齐；偏移 40 的两字节计数加一。
- 保留其他特征及随机状态；没有采集或虚构新的鼠标键盘行为。
- 只替换本次请求的 Cookie v，其余 Cookie 保持不变，不写回数据库、不改变登录 Cookie 生命周期。
- 格式、版本或校验异常时，在发请求前返回 SOURCE_VALIDATION_COOKIE_INVALID，提示重新保存完整 Cookie。
- 每次以已保存模板的计数加一，不在多个云实例之间持久化全局计数；本次验证未发现服务器要求跨请求连续递增，不能保证未来规则不变。
